# 8. Categories deliberately not targeted

Openness about scope — the remaining Devpost awards and why Loci does not
chase them. One entry can be considered across awards; covering *more*
categories with a weaker story would dilute the ones above.

## Best Social & Multiplayer Experience

**Why not targeted:** Loci's core loop is deliberately single-player and
local-first — a private thinking space. The palace stores no accounts, no
cloud, no shared state; the safety design (distress gate, crisis panel) is
built around one user's own thoughts. Multiplayer is a real roadmap item
([roadmap](../../README.md#roadmap) — "shared palaces for collaborative
thinking"), but shipping a thin social layer for the award would betray the
privacy-first design that other categories reward.

## Best Adapted / Significantly Updated *Experience* variants

**Why not targeted:** these honor existing flat products reworked for VR.
Loci was conceived and built **within the competition window** — first
commit inside it (`git log --reverse --format="%ai" | head -1`) — with no
pre-existing codebase. It enters as **New Experience** and **Best New
Productivity Experience**; entering the "Adapted" variants would misstate
what it is.

## Best New Gaming / Entertainment Experience

**Why not targeted:** wrong tracks for this entry. Loci is a productivity
and memory tool; its genre claims (ritual, recall, persistence) belong to
the Productivity track where the judging description matches the product
one-to-one.

## What this buys the strong categories

Every file in this folder argues from **shipped, verified features** — the
coverage table in [README.md](README.md) maps one file per award with
implementation maps and evidence. Concentrating the story on seven
well-matched awards keeps the demo video, the Devpost fields, and the docs
all pointing at the same strengths.
